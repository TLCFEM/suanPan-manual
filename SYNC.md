# Routine suanPan manual sync

This checklist updates the manual to a new upstream suanPan revision.

## Sources of truth

- `../suanPan` is the C++ source used for versioning, Doxygen output and factual verification.
- `Toolbox/command.h` holds `SUANPAN_MAJOR`, `SUANPAN_MINOR` and `SUANPAN_PATCH`.
- The upstream `CHANGELOG.md` and `README.md` list released changes and dependency versions.
- Command registries live in `Toolbox/command.cpp` and `Solver/SolverParser.cpp`.
- Storage schemes and solver containers live in `Domain/Factory.hpp` and `Domain/MetaMat/`.
- Step defaults and validation live in `Step/Step.cpp` and each `Step/<Name>.cpp`.

## Before starting

1. Record the upstream revision and version.

```bash
git -C ../suanPan fetch --tags
git -C ../suanPan log -1 --oneline
grep -nE 'constexpr auto SUANPAN_(MAJOR|MINOR|PATCH)' ../suanPan/Toolbox/command.h
```

2. Read the upstream `CHANGELOG.md` entries since the previous sync.
3. Confirm the manual working tree is clean.

## 1. Audit factual pages

- Compare command lists and aliases with the C++ registries.
- Compare solver names and their arguments with `Solver/SolverParser.cpp`.
- Compare storage and solver combinations with `Domain/Factory.hpp` and the step initialisers.
- Compare dependency versions with the upstream `README.md`.
- Update `docs/Collection/Configure/` and `docs/Collection/Process/set.md` when commands change.
- Update `docs/Library/Step/` when step defaults or validation change.
- Update `docs/Library/Solver/` when solver behaviour or supported backends change.
- Update `docs/Developer/Prerequisites.md` when dependency versions change.
- Remove retired keywords and modes from every page that mentions them.
- Prefer executable source over existing manual prose when they conflict.

## 2. Add or update pages

- Add new pages to the nearest `.pages` nav.
- Add new pages to `docs/SUMMARY.md` for GitBook.
- Keep paired `.md`/`.ipynb` examples in sync.
- Use `$$...$$` for all math, including inline expressions.
- Write one sentence per line and state facts only.

## 3. Verify

```bash
python -m pip install -e .
mkdocs build
mkdocs serve
git diff --check
git status --short
```

- `mkdocs build` executes non-ignored notebooks, so `suanpan` must be on `PATH`.
- `docs/Doxygen/` is regenerated by `setup.py` and is not committed.
- Check relative links after moving or renaming pages.

## 4. Commit

```bash
git add -A
git diff --cached --check
git commit -m "Sync with suanPan <version>"
```

- CI publishes `dev` and `master` with `mike deploy` using `SP_VERSION`.
- The `sync.yml` workflow mirrors pushed branches to GitLab and Codeberg.
