# AGENTS.md

## Repository

- Documentation-only MkDocs Material site for the separate suanPan C++ project.
- `docs/` is the site root; `.pages` files drive navigation via `mkdocs-awesome-pages-plugin` and Zensical's `awesome-nav`.
- `docs/SUMMARY.md` is the GitBook TOC; `.gitbook.yaml` and `book.json` target `docs/README.md` and `docs/SUMMARY.md`.
- `docs/Doxygen/` is generated by `setup.py` and is gitignored.
- `SYNC.md` at the repository root is the checklist for syncing with upstream suanPan.

## Setup and build

- `python -m pip install -e .` registers the `overwrite_math` plugin from `plugins/overwrite/`.
- `pip install -r requirements.txt` alone omits that plugin, which `mkdocs.yml` references.
- `setup.py` downloads the upstream `dev` source for the version and a suanPan release binary over the network.
- `mkdocs serve` previews locally; `mkdocs build` builds `site/`.
- `zensical.toml` mirrors `mkdocs.yml` for features supported by Zensical; `zensical build` uses it automatically.
- `zensical build` builds `site/`, copies `.ipynb` files without executing them, and requires no `suanpan` binary.
- Zensical uses the modern variant with a custom light/dark palette defined in `docs/zensical.css`.
- `plugins/overwrite/post_build.py` applies the `overwrite_math` rewrites to Zensical output because Zensical does not run MkDocs plugins.
- `mkdocs-jupyter` executes non-ignored `.ipynb` pages during an MkDocs build, so `suanpan` must be on `PATH`.
- `plugins/scripts/optimize_svg.py` optimizes built SVGs in place by batching them across parallel `svgo` processes, skipping `inherit_graph.*` names; CI and Read the Docs call it instead of invoking `svgo` directly.
- CI symlinks the downloaded `suanPan.sh` to `/usr/bin/suanpan` and checks `suanpan -v`.
- `doxygen` and `graphviz` are required for Doxygen output; no test, lint, or typecheck suite exists.

## Editing

- Add new pages to the relevant `.pages` nav and to `docs/SUMMARY.md`.
- Keep paired `.md`/`.ipynb` examples in sync; only the notebook form is executed at build.
- Use `$$...$$` for all math, including inline expressions.
- Write one sentence per line.
- Keep language concise and lean.
- State facts only; omit motivation and reasoning that can go stale when the suanPan source changes.
- Verify behaviour against the suanPan source (`Step/`, `Domain/Factory.hpp`, `Solver/`, `Toolbox/command.cpp`) before documenting solver or step details.

## CI and publishing

- `.github/workflows/dev.yml` covers pull requests and pushes to `dev`; `master.yml` covers pushes to `master`.
- Both pin `SP_VERSION: '4.4'` and publish with `mike deploy` to `gh-pages`.
- `dev.yml` skips deployment for commit messages containing `Bump`.
- `.readthedocs.yaml` installs the project to generate Doxygen output, builds with `zensical build`, runs the post-build math rewrites and SVGO optimization, and copies `site/` to `$READTHEDOCS_OUTPUT/html/`.
- Commit messages are short capitalized imperatives, e.g. `Update icons`.
